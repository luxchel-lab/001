# ArchiPaint — сервис подбора краски

Инструмент подбора цвета для сайта ArchiPaint. Собирает в одну страницу всё,
что нужно клиенту, чтобы выбрать оттенок и заказать его: подбор по фотографии,
поиск по коду чужого стандарта, поиск по координатам, гармонические схемы,
готовые интерьерные палитры, примерку в комнате и расчёт расхода.

Все расчёты идут в браузере — страница работает без внешнего API.
Если у проекта появится колеровочный сервис, он подключается одной строкой
и становится приоритетным источником данных, а локальный расчёт остаётся
запасным вариантом.

## Что умеет

**Подбор по фотографии**
- Перетаскивание, выбор файла, вставка из буфера (Ctrl+V), демо-сцена.
- Выделение 4 доминирующих цветов методом k-means++ в пространстве CIE Lab
  с отсевом выбитых в белое и почти чёрных пикселей. Инициализация
  детерминированная: одно и то же фото всегда даёт одну и ту же палитру.
- Пипетка с лупой и усреднением по области 5×5 — пятый цвет палитры.
- Для каждого цвета: доля в кадре, Lab, LCh, LRV и 3 ближайших оттенка каталога с ΔE.

**Поиск по коду цвета**
- Справочник RAL Classic (213 оттенков) с русскими названиями.
- Клиент вводит «RAL 7016» или «антрацит» — сервис показывает сам стандарт
  и подбирает, чем его закрыть из палитры ArchiPaint, с честным ΔE.
- Подсказки с первого символа, поиск одновременно по стандартам и своему каталогу.

**Поиск по координатам**
- HEX, RGB, CIE Lab, CIE LCh, HSL. Формат определяется автоматически,
  режим можно задать вручную.
- Предупреждение, если введённый Lab выходит за охват sRGB.

**Гармонические сочетания**
- 8 схем: монохромная, аналоговая, комплементарная, раздельно-комплементарная,
  триада, прямоугольник, квадрат, аналоговая с акцентом.
- **Углы схем откладываются по кругу Иттена, а не по тону LCh.** Схемы
  придуманы для художественного круга RYB, где красному отвечает зелёный,
  жёлтому — фиолетовый, синему — оранжевый. Поворот тона прямо в LCh даёт
  другое: красному там противостоит голубой, синему — жёлто-зелёный.
  `ittenToLch()` и `lchToItten()` переводят угол между кругами по двенадцати
  опорным тонам Иттена; их тон в LCh строго возрастает по кругу, поэтому
  перевод однозначен в обе стороны (проверено: ошибка обхода 0°). Шаг между
  опорами неравномерен — это свойство самого круга: голубую область он почти
  не различает. В LCh считается всё остальное — светлота, хрома, ΔE, подбор
  из каталога.
- Интерактивный цветовой круг в LCh с маркерами схемы.
- Второй вид — схема в объёме CIE Lab: ось светлоты вверх, оси a и b поперёк,
  срез охвата sRGB на светлоте базового цвета. Круг показывает только тон,
  и два цвета одного тона ложатся в одну точку, хотя различаются светлотой
  вдвое — а в интерьере именно светлота решает, что станет стенами, а что
  акцентом.
- Камера орбитальная: горизонтальное перетаскивание вращает сцену,
  вертикальное поднимает и опускает точку зрения. Крайние положения
  осмысленны сами по себе, и на них есть пресеты: «Сверху» даёт привычный
  цветовой круг, «Сбоку» — чистую шкалу светлоты, на которой сразу виден
  разброс схемы по L.
- Кадр подгоняется под содержимое: при наклоне сцена то вытягивается вверх,
  то расплывается вширь, и фиксированный масштаб оставлял бы половину холста
  пустой. Кромка среза считается по настоящей границе охвата на каждом тоне,
  а не отбрасыванием ячеек, поэтому край гладкий.
- Точки схемы пронумерованы, и те же номера стоят на карточках цветов
  справа: образец, HEX, L / C / h / LRV и ближайшая краска с ΔE. Наведение
  подсвечивает карточку и точку разом, клик открывает карточку цвета.
- Раскладка блока: базовый цвет, вкладки схем и описание идут во всю ширину,
  ниже двумя колонками — сцена слева, карточки справа. В узкой колонке семь
  вкладок разваливались на пять строк, а правая половина пустовала.
- Каждый цвет схемы сопоставлен с оттенком каталога.

**Интерьерные палитры**
- 12 настроений: от «Дыхания света» до «Ночной роскоши».
- Роли: стены, дополнительный, акцент, глубокий акцент, потолок, столярка.
- Доли площадей — 60/30/10 с поправкой на **контраст площади Иттена**
  (седьмой из его семи контрастов). Иттен взял светлоты чистых тонов по Гёте
  и потребовал, чтобы площади были им обратно пропорциональны: жёлтый
  «кричит» втрое сильнее фиолетового, поэтому его нужно втрое меньше.
  Отсюда пары жёлтый : фиолетовый = 1 : 3, оранжевый : синий = 1 : 2,
  красный : зелёный = 1 : 1 — сервис воспроизводит их точно. Правило выведено
  для чистых тонов, поэтому поправка ослабевает вместе с хромой и на
  приглушённой палитре сходит на нет. Порядок ролей она не переворачивает:
  стены остаются самой большой площадью.
- **Ведущий контраст**: из пяти измеримых контрастов Иттена (светлого
  и тёмного, холодного и тёплого, дополнительных, по насыщенности, цвета
  как такового) выбирается сильнейший и подписывается словами. Симультанный
  контраст измерению не поддаётся, контраст площади показан полосой.
- **Разбор огрехов**: спор тёплого и холодного подтона у близких по светлоте
  приглушённых цветов; смежные поверхности с разницей LRV меньше 5 —
  граница между ними не читается; потолок темнее стен. Срабатывает
  на 17% палитр — то есть указывает на настоящие случаи, а не шумит.
- Роль базового цвета определяется автоматически по близости к целевой светлоте
  роли в конкретном пресете — почти чёрный оттенок в светлой гамме станет
  акцентом, а в «Ночной роскоши» именно он и есть стены. Роль можно задать вручную.
- Оценка палитр звёздами, сохранение в библиотеку.

**Примерка в комнате**
- Семь помещений: гостиная, кухня, столовая, спальня, кабинет, ванная,
  прихожая. SVG, без внешних картинок.
- Сцена строится в координатах комнаты: u поперёк, v по высоте, d вглубь.
  `projector()` переводит их в экранные по правилам одноточечной перспективы,
  поэтому мебель стоит в объёме, а не наклеена на стену: у предметов сами
  собой получаются верхняя и боковая грани, тени ложатся по полу, а плинтус
  и карниз идут вдоль стен. Новое помещение стоит одной функции
  в `ROOM_BUILDERS`.
- `depth` в `ROOM_VIEWS` задаёт, насколько далеко дальняя стена: ванная
  и прихожая мельче жилых комнат. Рёбра комнаты сходятся в одну точку —
  границы дальней стены выводятся из глубины, а не подбираются на глаз.
- Каждая плоскость сначала заливается цветом краски, поверх ложится маска
  освещения: градиент от окна, тень в углах, световое пятно на полу, зерно.
  Цвет под маской остаётся ровно тем, что в банке.
- Роли палитры разложены по поверхностям: стены — «Стены», акцентная стена —
  «Акцент», мягкая мебель — «Дополнительный», дверь — «Глубокий акцент»,
  потолок и столярка — свои роли. Пол в палитру не входит и задаётся вручную.
- Кнопка «Купить» рядом с поверхностью открывает карточку краски этого оттенка.
- Комната освещена дневным светом из окна — той же белой точкой D65,
  в которой измеряют выкрасы.

**Калькулятор и корзина**
- Площадь стен считается по длине, ширине и высоте, но её можно ввести
  руками: у клиента часто есть готовая цифра из сметы, а комнату сложной
  формы тремя числами не задать. Кнопка «По размерам» возвращает автоподсчёт.
- Галочки «красим ещё и потолок» (добавляет длину × ширину) и «3D-панели
  и молдинги» (расход +20% на рельеф и подрезку граней).
- Расчёт расхода по площади, слоям и типу основания.
- Выбор краски из линеек Premium и Профи — расход берётся у продукта,
  фактура основания учитывается коэффициентом.
- Подбор фасовки: точный перебор, а не деление на большую банку. Три банки
  по 0,9 л почти всегда дороже одной на 2,7 л, и сервис это учитывает.
- Корзина в localStorage: рассчитанный объём, выкрасы и пробники, количество,
  итог. «Оформить заказ» отдаёт состав событием `archipaint:cart`.
- Моделирование нарушений цветовосприятия: протанопия, дейтеранопия,
  тританопия, ахроматопсия.
- Переключение формулы ΔE: CIEDE2000, CMC 2:1, CMC 1:1, CIE94, CIE76.
- Фильтр по коллекциям, избранное, сравнение до 4 цветов.
- Экспорт палитры в JSON и PNG, печать, ссылка с состоянием подбора.
- Горячие клавиши: `P` — пипетка, `K` — каталог, `/` — поиск по коду, `Esc` — закрыть.

```
podbor.php                    страница Bitrix
assets/css/podbor.css         стили инструмента
assets/js/podbor.color.js     цветовая математика (не зависит от DOM)
assets/js/podbor.palette.js   каталог ArchiPaint, 288 оттенков  [генерируется]
assets/js/podbor.standards.js справочник RAL Classic, 213       [генерируется]
assets/js/podbor.data.js      каталог, пресеты, роли, построение палитр
assets/js/podbor.js           интерфейс, точка входа podbor()
demo/index.html               автономная демонстрация           [генерируется]
tools/build-palette.js        генератор каталога
tools/build-standards.js      генератор справочника стандартов
tools/ral-source.txt          исходные данные RAL Classic
tools/build-demo.js           сборка демо-страницы из podbor.php
tools/measure-density.js      замер плотности каталога (какие ΔE увидит клиент)
```

Файлы, помеченные `[генерируется]`, вручную не редактируются.

```bash
node tools/build-palette.js     # пересобрать каталог
node tools/build-standards.js   # пересобрать справочник RAL
node tools/build-demo.js        # пересобрать демо-страницу
```

## Установка в Bitrix

1. Скопируйте `assets/` в корень сайта (`/assets/...`).
2. Положите `podbor.php` в нужный раздел, например `/service/podbor/index.php`.
3. Откройте страницу. Никаких дополнительных модулей и библиотек не требуется —
   jQuery инструменту не нужен.

Порядок подключения скриптов важен: `color` → `palette` → `standards` → `data` → `podbor`.
В `podbor.php` он уже задан.

## Подключение колеровочного API

По умолчанию сервис считает всё локально. Чтобы задействовать внешний API,
передайте его адрес при инициализации в `podbor.php`:

```js
podbor({
  apiBase: 'https://color-api.archipaint.ru',
  logEvents: true
});
```

Используются два эндпоинта; при недоступности любого из них сервис молча
переходит на локальный расчёт, поэтому страница не ломается.

**`GET /api/v1/catalog/colors?q=<запрос>&limit=<n>`** — поиск по каталогу.
Ответ: массив (или `{ items: [...] }`) записей:

```json
{ "color_code": "AP-0224", "color_name": "Кремень", "hex": "#2C3136",
  "lab": { "l": 20.0, "a": -0.9, "b": -3.9 }, "collection": "ArchiPaint Minerals" }
```

Допустимы плоские поля `lab_l` / `lab_a` / `lab_b`. Если `lab` не пришёл,
координаты рассчитываются из `hex`.

**`POST /api/v1/palettes/interior/harmonies`** — интерьерные палитры.
Тело: `{ baseColor, presetId, schemes, baseRoleOverride? }`.
Ответ должен содержать непустой `results` в том же виде, что возвращает
`ArchiPaintData.buildInteriorPalettes()`, иначе используется локальный результат.

**`POST /api/v1/frontend-events`** — аналитика. Отправляется только при
`logEvents: true`. События: `standard_lookup`, `interior_palettes_shown`,
`palette_rating`, `order_intent`.

Локальный расчёт показывается сразу, не дожидаясь сети, а ответ API приходит
следом и уточняет результат. Если пользователь успел сменить цвет или
настроение, запоздавший ответ отбрасывается.

**Если API живёт на отдельном домене**, учтите: запрос палитр отправляется
с `credentials: 'include'` (сессионная кука нужна для лимитов и кабинета).
Такой запрос требует, чтобы сервер возвращал конкретный `Access-Control-Allow-Origin`
(не `*`) и `Access-Control-Allow-Credentials: true`. При `*` браузер молча
заблокирует ответ, и сервис уйдёт на локальный расчёт — внешне всё
продолжит работать, но API окажется не у дел. На одном домене с сайтом
(обычный случай для Bitrix) вопрос не возникает.

## Подключение корзины

Сервис ведёт свою корзину в localStorage и параллельно отдаёт отменяемые
DOM-события. Перехватите их и вызовите `preventDefault()`, чтобы подавить
встроенные уведомления-заглушки и увести клиента в корзину Bitrix.

```js
// одна позиция: выкрас, пробник или банка из карточки цвета
document.addEventListener('archipaint:order', function (e) {
  e.preventDefault();
  // e.detail: { colorCode, colorName, hex, collection, optionId, volume, price }
  BX.ajax.post('/local/ajax/add-to-basket.php', e.detail);
});

// оформление всей корзины целиком
document.addEventListener('archipaint:cart', function (e) {
  e.preventDefault();
  // e.detail: { items: [{ productSku, productName, volume, volumeLabel,
  //                       price, qty, colorCode, colorName, hex }], total }
  BX.ajax.post('/local/ajax/checkout.php', e.detail);
});
```

## Программный доступ

```js
ArchiPaintUI.setActiveColor('#8C4A3E', 'из каталога'); // перестроить палитры
ArchiPaintUI.openColorCard(ArchiPaintData.getByCode('AP-0224'));
ArchiPaintUI.refresh();

ArchiPaintColor.deltaE(lab1, lab2, 'cmc21');
ArchiPaintData.searchStandards('7016');
ArchiPaintData.buildInteriorPalettes('#8C4A3E', 'earthy_warm', {});
```

`podbor.color.js` не зависит ни от DOM, ни от jQuery — его можно подключить
через `require()` в Node и использовать на сервере.

## Каталог красок: расход, фасовка, цены

`PRODUCTS` в `assets/js/podbor.data.js` — рабочая заготовка по линейкам
Premium и Профи. **Расход, фасовка и цены проставлены ориентировочно и должны
быть заменены данными товароведа перед публикацией.** Это единственное место,
где они заданы:

```js
{ sku: 'PM-MATT', name: 'Premium Matt', line: 'Premium', sheen: 'Глубокоматовая',
  use: 'Стены и потолки жилых комнат',
  coverage: 12,                       // м²/л в один слой на гладком основании
  cans: [{ v: 0.9, price: 1290 }, { v: 2.7, price: 3390 }, { v: 9, price: 9900 }] }
```

Фактура основания учитывается отдельно — коэффициентом `factor` из `SURFACES`.

## Замена каталога на реальные данные

`assets/js/podbor.palette.js` — справочный набор из 288 оттенков, построенный
по 12 цветовым семьям (8 ступеней светлоты × 3 ступени насыщенности).
Он нужен, чтобы инструмент работал сразу, и рассчитан на замену.

Подставьте выгрузку реальных спектрофотометрических измерений в том же формате:

```js
window.ARCHIPAINT_PALETTE = [
  { code: 'AP-0224', name: 'Кремень', hex: '#2C3136',
    family: 'Холодные нейтральные', familyId: 'grey',
    collection: 'ArchiPaint Minerals', lab: [20.0, -0.9, -3.9] }
];
```

Либо оставьте файл как запасной вариант и подключите API — приоритет будет у него.

Чем плотнее каталог, тем меньше ΔE до ближайшего оттенка. Замеры на
нынешних 288 оттенках (`node tools/measure-density.js`):

| Выборка | Средний ΔE₀₀ до ближайшего |
|---|---|
| Интерьерный диапазон (хрома < 38) | **4,4** |
| Произвольные цвета sRGB | 9,7 |

Для веера такого размера это ожидаемо — RAL Classic содержит 213 оттенков,
Farrow & Ball — 132. Но клиент видит ΔE в интерфейсе, поэтому подмена
каталога на реальную выгрузку — самый заметный способ улучшить сервис:
на палитре в 1500–2000 оттенков средний ΔE в интерьерном диапазоне
опускается примерно вдвое.

## Точность и её границы

Считается честно:
- CIEDE2000 сверена со всеми 31 контрольными парами из набора
  Sharma, Wu & Dalal (2005) — расхождение меньше 10⁻⁴.
- Преобразования sRGB ↔ XYZ ↔ Lab ↔ LCh для D65, наблюдатель 2°;
  обратимость проверена на сетке sRGB и на всём каталоге.
- CMC(l:c), CIE94, CIE76 — по стандартным формулам.
- LRV рассчитывается как координата Y в XYZ.
- Контраст и уровни AA/AAA — по WCAG 2.1.

Приблизительно, и так и подписано в интерфейсе:
- **Моделирование дальтонизма** — матрицы в приближении Machado et al.
- **HEX внешних стандартов** — общепринятые экранные приближения. Они не
  заменяют физический веер.

Цвет на экране всегда отличается от выкраса: монитор не откалиброван,
краска имеет фактуру и по-разному отражает свет. Поэтому в каждой карточке
первым предложением стоит выкрас на бумаге.

## Калькулятор: цвет и площадь по поверхностям

Цвет выбирается списком: активный оттенок подбора, семь поверхностей примерки
(стены, акцентная стена, потолок, столярка, мебель, дверь, пол) и пункт «выбрать
другой оттенок из каталога» — он открывает каталог в режиме возврата выбранного
цвета. Список пересобирается по событиям `archipaint:activecolor`
и `archipaint:surfaces`.

Выбор поверхности задаёт и способ расчёта площади:

| Поверхность | Площадь | Проёмы |
|---|---|---|
| Стены, активный цвет, цвет из каталога | 2 × (длина + ширина) × высота | вычитаются |
| Акцентная стена | большая сторона × высота | нет |
| Потолок, пол | длина × ширина | нет |
| Столярка, мебель, дверь | только вручную | нет |

Проёмы вычитаются лишь из стен: на потолке или двери вычитать нечего, а
оставленные там 6 м² уводили площадь в минус и результат не показывался.
Поле площади и его подпись идут за выбором, а чекбокс «красим ещё и потолок»
показывается только в режиме стен.

В корзину поверхность попадает отдельной строкой (она входит в ключ позиции),
поэтому «Стены · AP-0111» и «Потолок · AP-0111» не схлопываются в одну строку —
клиент собирает заказ на комнату за несколько заходов и видит, что к чему.

## Пересборка при смене базового цвета

Событие `archipaint:activecolor` перестраивает всё, что зависит от базового
цвета: палитру фото, гармонии, ряд «Настроение палитры» и сами интерьерные
палитры. Полоски настроений строятся вызовом `buildInteriorPalettes` от текущего
цвета, поэтому их тоже нужно пересобирать — иначе ряд остаётся от прошлого
оттенка и обновляется только кликом по карточке.

## Построение палитр от базового цвета

Проверяется скриптами аудита по 4320 палитрам (20 баз × 12 настроений ×
3 роли × 6 схем):

* базовый цвет входит в палитру ровно таким, каким выбран, и стоит
  в заявленной роли — 4320 из 4320;
* углы схем отложены по кругу Иттена: максимум 4° расхождения, и то
  на цвете с хромой 9, где тон съедается округлением до 8 бит;
* порядок светлот ролей не нарушается — 0 случаев;
* доли площадей складываются ровно в 100%.

Два места правились по итогам аудита.

**Потолок темнее стен.** Ограничение `minL` поднимало целевую светлоту потолка
до уровня стен, но подбор по каталогу об этом не знал и брал ближайший по ΔE
цвет — тот оказывался ниже цели. Теперь ограничение уходит в сам поиск
(`findNearest`, параметр `minL`), а если светлее в каталоге ничего нет, берётся
лучшее, что есть. Осталось 138 случаев из 4320 — все на чистом белом
`#FFFFFF` в роли стен: светлее AP-0101 (LRV 90) в каталоге нет, и это
ограничение веера, а не расчёта.

**Дедуп ломал порядок светлот.** Совпавший каталожный код `dedupeByCode`
сдвигал по светлоте, пробуя направление «сначала вверх». Глубокий акцент
всплывал светлее обычного — L44 против L32. Направление теперь выбирается
по смыслу роли (тёмные темнеют, светлые светлеют), а сдвиг ограничен 24
единицами L: максимальный увод от цели упал с 20,1 до 13,9.

## Ширина текстовых блоков

Пояснения секций (`.sub`, `.section-intro`, `.scheme-desc`) занимают всю ширину
своей карточки. Раньше они были обрезаны по 62–78 `ch`: на широком мониторе
строка кончалась примерно на середине блока, и правая половина карточки
оставалась пустой. Ограничение снято одним правилом в `podbor.css`, ширину
строки задаёт сама колонка — на узком экране она сужается вместе с сеткой.

## Проверка

Разметка и модули проверяются так:

```bash
php -l podbor.php
for f in assets/js/*.js; do node --check "$f"; done
node tools/build-palette.js && node tools/build-standards.js && node tools/build-demo.js
node tools/measure-density.js
```

Для ручной проверки откройте `demo/index.html` — это та же вёрстка, что и в
`podbor.php`, собранная в автономную страницу.

## Поддержка браузеров

Chrome, Firefox, Safari, Edge — актуальные версии и две предыдущие.
Используются `canvas`, `fetch`, `CSS Grid`, `aspect-ratio` и пользовательские
свойства CSS. Внешних зависимостей нет.

# ArchiColor AI — прототип визуализатора краски

Витринная версия интеграции с Decor8.ai: **фронтенд сделан набело в двух
вариантах вёрстки, бэкенд — заглушки**. Показывать можно как есть, ничего
не настраивая.

```
archi-ai/
├── bootstrap/index.html      вариант 1 — вёрстка на Bootstrap 4
├── custom/index.html         вариант 2 — авторская вёрстка без фреймворка
├── assets/
│   ├── css/archi_ai.bootstrap.css   надстройка над Bootstrap
│   ├── css/archi_ai.css             авторские стили
│   ├── js/archi_ai.js               общий скрипт для обоих вариантов
│   └── vendor/bootstrap/            Bootstrap 4.6.2 локально
└── api/                      заглушки бэкенда (PHP)
```

## Как посмотреть

```bash
php -S 127.0.0.1:8080 -t .
# затем открыть
#   http://127.0.0.1:8080/archi-ai/bootstrap/
#   http://127.0.0.1:8080/archi-ai/custom/
```

Демо-вход: любой номер, код **1234**. Кнопка «Взять демо-фото» рисует комнату
на canvas — свой снимок не обязателен.

Страницы открываются и просто файлом, без PHP: скрипт заметит, что бэкенда
нет, покажет плашку и перейдёт на клиентскую имитацию перекраски. Сценарий
останется целым.

## Два варианта вёрстки

| | Bootstrap 4 | Авторский |
|---|---|---|
| Сетка и компоненты | Bootstrap: `container`, `row`, `card`, `btn` | своя сетка на CSS Grid |
| Характер | светлый, карточный, «корпоративный» | тёмный студийный герой, антиква, широкие поля |
| Свои классы | 42 шт., все `archi_ai-*` | 65 шт., все `archi_ai-*` |
| JS Bootstrap | не подключается (требует jQuery) | не нужен |

**Все собственные классы начинаются с `archi_ai-`.** В бутстраповском варианте
рядом живут родные классы фреймворка (`container`, `row`, `col-*`, `card`,
`btn`, утилиты) — их переименовывать нельзя, иначе Bootstrap перестанет
работать. В авторском варианте посторонних классов нет вовсе.

Служебные состояния — `is-open`, `is-active`, `is-over`, `is-low`, `is-out`,
`is-busy` — навешивает скрипт, и они одинаковы для обеих вёрсток.

**Тег `main` не используется** ни в одной из вёрсток: секции размечены
обычными `div`, `section`, `header` и `footer`.

## Один скрипт на две вёрстки

`assets/js/archi_ai.js` не знает ни одного классового имени. Все зацепки —
через `data`-атрибуты:

```html
<div data-archi="drop">           <!-- зона загрузки -->
<button data-archi="submit">      <!-- кнопка примерки -->
<div data-archi="stageResult">    <!-- блок результата -->
```

Поэтому обе вёрстки обслуживает одна логика, и третий вариант дизайна можно
добавить, не трогая JS.

## Заглушки бэкенда

| файл | что изображает |
|---|---|
| `api/quota.php` | остаток бесплатных примерок и баланс баллов |
| `api/palette.php` | палитра ArchiPaint (24 оттенка для демо) |
| `api/auth-request-code.php` | отправка кода в SMS |
| `api/auth-verify.php` | проверка кода, выдача сессии |
| `api/auth-logout.php` | выход |
| `api/generate.php` | вызов Decor8 `/change_wall_color` и разбор на цвета |
| `api/balance-topup.php` | создание платежа в ЮKassa |
| `api/demo-payment.php` | экран оплаты вместо страницы ЮKassa |
| `api/webhook-yookassa.php` | уведомление об оплате и начисление баллов |
| `api/cashback.php` | кэшбэк с заказа краски |
| `api/history.php` | история движений баллов |

В каждом файле под заголовком **«ЧТО ДОЛЖЕН ДЕЛАТЬ НАСТОЯЩИЙ БЭКЕНД»**
описано, чем именно заменить заглушку: какие запросы к Decor8 и ЮKassa
отправлять, где нужна атомарность, где — защита от повторного начисления.

Формат ответов совпадает с боевым, поэтому подмена заглушки на реализацию
не потребует править ни строчки JS.

Чего заглушки **не делают** — и что придётся написать:

- нет базы данных: вход, счётчик примерок и баланс живут в PHP-сессии,
  то есть у каждого посетителя свои и до перезапуска браузера;
- нет проверки кода из SMS — подойдёт `1234` или любые шесть цифр;
- нет вызова Decor8: стены «перекрашиваются» тонированием верхней части
  кадра средствами GD, распознавания стен там нет;
- нет вызова ЮKassa: экран оплаты и вебхук имитируются локально;
- ΔE и доли тонов в разборе — правдоподобные числа, а не расчёт.

Рабочая реализация всего перечисленного лежит в `lib/archicolor/` и
`api/archicolor/` — прототип её не использует и не затрагивает.

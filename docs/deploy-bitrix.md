## 0. Что это и чего от тебя нужно

Готовая страница подбора краски: подбор по фотографии, поиск по коду RAL
и по координатам, гармонические сочетания, интерьерные палитры, примерка
в комнате на фото, калькулятор расхода, корзина и промпт для ArchiColor AI.

Всё считается **в браузере**. Ни PHP-логики, ни базы, ни внешнего API для
работы не нужно — страница поднимается копированием файлов.

От тебя требуется:

1. выложить файлы на сайт (раздел 2);
2. подключить корзину Bitrix к событиям инструмента (раздел 5) — **обязательно**,
   иначе кнопки «Купить» показывают заглушку;
3. заменить заглушечные данные по товарам на реальные (раздел 6) — **обязательно
   перед публикацией**, там сейчас выдуманные цены;
4. прогнать приёмку (раздел 9).

Остальное — по желанию и по мере готовности смежных сервисов.

## 2. Выложить на сайт

### 2.1. Ассеты

Скопируй папку `assets/` в корень сайта, чтобы получилось:

```
/assets/css/podbor.css
/assets/js/podbor.color.js
/assets/js/podbor.palette.js
/assets/js/podbor.standards.js
/assets/js/podbor.data.js
/assets/js/podbor.photo.js
/assets/js/podbor.js
/assets/rooms/living.photo.png
/assets/rooms/living.mask.png
… ещё 4 комнаты: dining, kitchen, bedroom, office
```

Если ассеты у нас лежат в шаблоне, а не в корне — можно и так, но тогда
правь два места:

- пути в `Asset::getInstance()->addCss/addJs` в начале `podbor.php`;
- параметр `roomsBase` при инициализации в конце `podbor.php`:

```js
podbor({ roomsBase: '/local/templates/main/rooms/' });
```

Слеш на конце обязателен.

### 2.2. Страница

`podbor.php` положи как страницу раздела, например
`/service/podbor/index.php`.

Внутри проверь и при необходимости поправь:

- `require($_SERVER["DOCUMENT_ROOT"]."/bitrix/header.php")` и такой же
  `footer.php` в конце — если у нас другой шаблон подключения, замени;
- `$APPLICATION->SetPageProperty("title" / "description")` и
  `$APPLICATION->SetTitle("Подбор цвета")` — тексты уже написаны под SEO,
  меняй только если есть свои;
- пути к ассетам, если они не в корне.

Больше в PHP менять нечего: вся логика в JS.

### 2.3. Порядок подключения скриптов — важен

```
color → palette → standards → data → photo → podbor
```

В `podbor.php` он уже задан через `Asset::getInstance()->addJs(..., true)`
(второй аргумент `true` = отложенная загрузка в конец). **Не меняй порядок
и не переводи на асинхронную загрузку по отдельности** — `data.js` на старте
читает `window.ARCHIPAINT_PALETTE`, который объявляет `palette.js`.

Если у нас включена оптимизация Bitrix (объединение и минификация JS),
проверь, что она сохраняет порядок. Инструмент минификацию переживает,
но перестановку файлов — нет.

### 2.4. jQuery не нужен

Инструмент ни от чего не зависит. Если jQuery на странице есть — не мешает.

## 4. Проверка после выкладки

Открой страницу и пройди по шагам:

1. **Загрузка фото.** Перетащи любой снимок интерьера → появляется палитра
   из 5 цветов с подбором из каталога и ΔE.
2. **Пипетка.** Кнопка «Пипетка» → клик по фото → цвет уходит в базовый.
3. **Поиск в шапке.** Введи `RAL 7016` → подсказка → выбор → секция
   «Найденный цвет». Потом `#293133`, потом `Lab 46 32 28` — должны
   определяться как координаты.
4. **Гармонии.** Переключи вкладки схем — круг, объём Lab и цвета меняются.
5. **Интерьерная палитра.** Сетка из 8 схем открыта сразу; клик по карточке
   переключает и вкладку наверху.
6. **Примерка.** Пять вкладок помещений; смена комнаты с перекраской кадра
   занимает около 0,34 с, полная перерисовка палитр — около 75 мс (замерено
   в Chromium на демо-сборке).
   Если кадры не грузятся — путь `roomsBase` неверный, см. 2.1.
7. **Калькулятор.** Введи размеры → расход, банки, цена.
8. **Корзина.** «В корзину» → позиция появляется в блоке «Корзина».
9. **Промпт для ArchiColor AI.** Кнопка под палитрой → окно с промптом и
   ссылкой на сервис.

В консоли не должно быть ошибок. Если что-то из списка не работает —
почти всегда это путь к ассетам или порядок скриптов.

## 5. Корзина Bitrix — обязательно

Инструмент ведёт свою корзину в `localStorage` и **параллельно** шлёт
отменяемые DOM-события. Перехвати их, вызови `preventDefault()` — это
подавит встроенные заглушки — и уведи клиента в нашу корзину.

```js
// одна позиция: выкрас, пробник или банка из карточки цвета
document.addEventListener('archipaint:order', function (e) {
  e.preventDefault();
  // e.detail: { colorCode, colorName, hex, collection,
  //             optionId, volume, price }
  BX.ajax.post('/local/ajax/add-to-basket.php', e.detail);
});

// оформление всей корзины целиком
document.addEventListener('archipaint:cart', function (e) {
  e.preventDefault();
  // e.detail: { items: [{ productSku, productName, volume, volumeLabel,
  //                       price, qty, colorCode, colorName, hex }],
  //             total }
  BX.ajax.post('/local/ajax/checkout.php', e.detail);
});
```

Вешай слушатели до вызова `podbor()` или сразу после — порядок неважен,
события всплывают на `document`.

**Что решить с товароведом:** как колерованная краска ложится в каталог
Bitrix. Вариантов два — торговое предложение на каждый SKU с ценой
колеровки как допуслуги, либо один товар «колеровка» с передачей кода
цвета в свойстве позиции. От этого зависит формат `add-to-basket.php`.

### Ключи localStorage

Префикс задаётся опцией `storagePrefix`, по умолчанию `archipaint:`:

| Ключ | Что хранит |
|---|---|
| `archipaint:favorites` | избранные цвета |
| `archipaint:cart` | корзина инструмента |
| `archipaint:palettes` | сохранённые палитры, до 40 |
| `archipaint:recent` | последние цвета, до 24 |
| `archipaint:ratings` | оценки палитр звёздами |

Если на сайте уже есть что-то с таким префиксом — смени его в
`podbor({ storagePrefix: 'ap-podbor:' })`.

## 6. Данные по товарам — обязательно заменить

В `assets/js/podbor.data.js` есть два массива с **выдуманными числами**.
Пока они не заменены, калькулятор считает неправильные деньги.

### 6.1. `PRODUCTS` (около строки 1224)

```js
{ sku: 'PM-MATT', name: 'Premium Matt', line: 'Premium',
  sheen: 'Глубокоматовая',
  use: 'Стены и потолки жилых комнат',
  coverage: 12,                     // м²/л в один слой на гладком основании
  cans: [ { v: 0.9, price: 1290 },  // объём в литрах и цена банки
          { v: 2.7, price: 3390 },
          { v: 9,   price: 9900 } ] }
```

Девять позиций: `PM-MATT`, `PM-SEMI`, `PM-RESIST`, `PR-BASE`, `PR-FASAD`,
`PR-AMBER`, `PR-BIOFIX`, `PR-LATESSA`, `PR-GLOSSA`.

Нужны от товароведа: реальный `coverage`, реальная фасовка и цены.
`sku` желательно привести к нашим артикулам в 1С — тогда они поедут
в корзину как есть.

### 6.2. `SURFACES` (около строки 1204)

Коэффициенты фактуры основания:

```js
{ id: 'plaster', label: 'Гладкая штукатурка / шпаклёвка',
  consumption: 11, factor: 1.0 }
```

`factor` — во сколько раз основание съедает больше краски. Значения взяты
по общей практике; если у технолога есть свои — подставь.

### 6.3. Мелкие позиции (около строки 1186)

Выкрас на бумаге 190 ₽, пробник 50 мл 490 ₽ и банки 1 / 2,7 / 9 л в карточке
цвета — тоже заглушки.

## 7. Каталог цветов — заменить на реальный

`assets/js/podbor.palette.js` — **демонстрационный** веер из 288 оттенков,
построенный математикой: 12 цветовых семей × 8 ступеней светлоты × 3 ступени
насыщенности. Он нужен, чтобы инструмент работал сразу, и рассчитан на замену.

Настоящих артикулов и названий в нём нет намеренно. Коды начинаются с
`DEMO-`, названия — это измеренные светлота и хрома («Охра и золото 66/30»),
коллекции называются «Демо · земляные» и так далее. Так заглушку невозможно
принять за колеровочную палитру, а артикул — случайно отправить в заказ.

Пока подключён такой каталог, страница сама показывает полосу вверху:
«Каталог демонстрационный». Признак вычисляется из префикса артикулов
(`ArchiPaintData.isDemoCatalog()`), отдельного флага в настройках нет —
его забыли бы переключить. Как только `window.ARCHIPAINT_PALETTE` заполнится
настоящей выгрузкой, полоса погаснет сама.

Формат:

```js
window.ARCHIPAINT_PALETTE = [
  { code: '<артикул>', name: '<название>', hex: '#2C3136',
    family: 'Холодные нейтральные', familyId: 'grey',
    collection: '<коллекция>',
    lab: [20.0, -0.9, -3.9] }   // L, a, b — D65, 2°
];
```

**Lab должен быть из спектрофотометра, а не пересчитан из HEX.** Именно
Lab определяет, что клиент увидит как «совпадение»: сейчас средний ΔE
подбора 3,98, а доля промахов больше 5 — 23 %. На реальной палитре
в 1500–2000 оттенков средний ΔE в интерьерном диапазоне падает примерно
вдвое.

Замерить плотность новой палитры: `node tools/measure-density.js`.

Альтернатива без правки файла — отдавать каталог по API, см. раздел 10.

## 8. Кадры комнат — заменить на фотографии

Сейчас в `assets/rooms/` лежат **синтетические пластины**, отрисованные
трассировщиком из `tools/build-room-scene.js`. Они показывают, что конвейер
работает, но это не фотографии.

Движку перекраски происхождение кадра безразлично — ему нужны светотень
снимка и маска. Чтобы поставить настоящие фотографии, нужна пара файлов
на комнату:

### `<id>.photo.png` — сам кадр

- 1000×660 px, PNG, colorType 2 (RGB без альфы);
- ровный дневной свет, никаких цветных источников — иначе перекраска
  потянет чужой подтон;
- стены лучше снимать светлыми: движок умножает светлоту, а не заменяет,
  и на тёмном исходнике светлая краска не получится.

### `<id>.mask.png` — маска поверхностей

- те же 1000×660, PNG, colorType 4 (серый + альфа);
- **серый = номер поверхности**, альфа = насколько пиксель ей принадлежит
  (для мягкой границы);

| Значение серого | Поверхность |
|---|---|
| 0 | не красится: окно, ковёр, стекло |
| 1 | `wall` — стены |
| 2 | `accentWall` — акцентная стена |
| 3 | `ceiling` — потолок |
| 4 | `trim` — плинтус и столярка |
| 5 | `furniture` — мягкая мебель |
| 6 | `door` — дверь |
| 7 | `floor` — пол |

Пять комнат: `living`, `dining`, `kitchen`, `bedroom`, `office`.
Список и подписи — в `SCENES` в `assets/js/podbor.photo.js`.

Подробный разбор движка — в `docs/room-preview.md`.

## 9. Приёмка

Сдано, когда:

- [ ] страница открывается по боевому адресу, в консоли пусто;
- [ ] все девять проверок из раздела 4 проходят;
- [ ] нет горизонтальной прокрутки на 390, 620, 900, 1100 и 1440 px;
- [ ] «В корзину» кладёт позицию в корзину Bitrix, а не показывает заглушку;
- [ ] калькулятор считает по реальным ценам и расходу;
- [ ] кнопка «Распечатать» в шапке интерьерной палитры даёт читаемый лист —
  печатные стили в CSS есть;
- [ ] горячие клавиши: `P` (или `З`) — пипетка, `K` (или `Л`) — каталог,
  `/` — фокус в строку поиска, `Esc` — закрыть окно;
- [ ] на телефоне работают загрузка фото с камеры и пипетка по тапу.

## 10. Необязательное: колеровочный API

По умолчанию всё считается локально. Если появится колеровочный сервис,
он подключается одной строкой в `podbor.php`:

```js
podbor({ apiBase: 'https://color-api.archipaint.ru', logEvents: true });
```

Три эндпоинта. **При недоступности любого сервис молча уходит на локальный
расчёт** — страница не ломается, клиент ничего не замечает.

**`GET /api/v1/catalog/colors?q=<запрос>&limit=<n>`** — поиск по каталогу.
Ответ: массив или `{ items: [...] }`:

```json
{ "color_code": "<артикул>", "color_name": "<название>", "hex": "#2C3136",
  "lab": { "l": 20.0, "a": -0.9, "b": -3.9 },
  "collection": "<коллекция>" }
```

Допустимы плоские `lab_l` / `lab_a` / `lab_b`. Без `lab` координаты
считаются из `hex`.

**`POST /api/v1/palettes/interior/harmonies`** — интерьерные палитры.
Тело: `{ baseColor, presetId, schemes, baseRoleOverride? }`.
Ответ должен содержать непустой `results` в том же виде, что отдаёт
`ArchiPaintData.buildInteriorPalettes()`.

**`POST /api/v1/frontend-events`** — аналитика, только при `logEvents: true`.
События: `standard_lookup`, `interior_palettes_shown`, `palette_rating`,
`order_intent`, `checkout_intent`, `ai_prompt_built`.

Таймаут — 8 с (`apiTimeout`). Локальный результат показывается сразу, ответ
API приходит следом и уточняет. Если клиент успел сменить цвет или характер
гаммы, запоздавший ответ отбрасывается.

**Если API на отдельном домене:** запрос палитр идёт с
`credentials: 'include'`. Сервер обязан вернуть конкретный
`Access-Control-Allow-Origin` (не `*`) и `Access-Control-Allow-Credentials: true`.
При `*` браузер молча заблокирует ответ, сервис уйдёт на локальный расчёт —
внешне всё работает, но API не у дел. На одном домене вопроса нет.

## 11. Стык с ArchiColor AI

Кнопка «Промпт для ArchiColor AI» под интерьерной палитрой собирает задание
на перекраску фотографии клиента. Клиент копирует русский текст и идёт на
`archipaint.ru/help/archicolor-ai`.

Сейчас это ручной стык: текст в буфер, дальше руками. Что стоит доделать
на стороне archicolor-ai — подробно в `docs/archicolor-prompt.md`, коротко:

1. **Брать цвета из `payload.surfaces`, а не из текста.** Функция
   `ArchiPaintData.buildAiPrompt()` возвращает `{ prompt, negative, ru,
   payload }`. В `payload.surfaces` лежит поверхность → HEX + артикул +
   LRV + доля площади. Текстом точный HEX задать нельзя в принципе; в одном
   из прогонов движок дал ΔE 30 на мягкой мебели и раздул акцент с
   заявленных 10 % до четверти кадра.
2. **Отправлять английский `payload.prompt`, а не русский.** В основе
   Decor8, английский он понимает заметно лучше. Русский текст существует
   для клиента.
3. **Подставлять `payload.negativePrompt`** — из клиентского текста он убран
   намеренно, это настройка запроса.
4. **Открытый вопрос:** возвращает ли archicolor-ai маски поверхностей?
   Если да — перекраска в Lab даёт ΔE < 1, и можно переиспользовать
   `assets/js/podbor.photo.js`. Если нет — остаётся чистая генерация,
   и точность артикула не гарантируется. От ответа зависит вся схема стыка.
